  System") created empty, with no sync yet. This repo has no design system
  code (`design/` is only a placeholder, with no `package.json`,

- Project `1c960ca8-5e00-4558-8ced-80dfbdf01027` ("Brabo Design
  System", same name) is of type `PROJECT_TYPE_PROJECT` (a plain project),
  not `PROJECT_TYPE_DESIGN_SYSTEM`; it cannot be used as a sync target (the
  type is set at creation and does not change afterwards). Do not confuse the
  two.
- 2026-07-26: first real import. The design system is **not** in
  `design/` (which remains only markdown docs); it is `apps/web`, shape
  `package`, `srcDir: src/components`. The `design/*.md` files enter as
  `guidelinesGlob`.
- The `projectId` was already pinned in the config before this run, so the
  router in §1 sends it down the **atomic path** (a single upload at the end),
  even with the project empty. Do not open an incremental `finalize_plan` here.
- **`.design-sync/preview-surface.tsx` is mandatory.** The converter's card
  template fixes `body{background:#fff}` in an inline `<style>` *after* the
  stylesheets, and this DS is dark-primary; without the wrapper via
  `cfg.provider`, all 57 cards render light-on-light and the render check marks
  icons and text as `blank`/`thin`. The file explains why the fix is a provider
  and not CSS. It is not a DS component: it stays in `componentSrcMap` as
  `null`.
- **Fonts**: they enter through a CDN `@import` in `.design-sync/fonts.css`,
  pulled in by `styles-entry.ts` (which also imports `apps/web/src/index.css`,
  in that order, so the tokens enter the esbuild graph). `cssEntry` does not
  work: it is limited to PKG_DIR and is concatenated at the END of
  `_ds_bundle.css`, where an `@import` is ignored.
- **`typescript` in `.ds-sync/node_modules` must be 6.x.** `npm i
  typescript` brings 7.x, whose root export is only `lib/version.cjs`; without
  `createSourceFile`, the `[DTS_PARSE]` check falls into the catch and is
  reported as "skipped" instead of failing. `npm i -E typescript@6.0.2` (the
  same one `apps/web` uses) makes the check run.

- **`--node-modules` is the ROOT `node_modules`, not the one in `apps/web`.**
  pnpm only creates the workspace self-link (`node_modules/web -> ../apps/web`)
  at the root; `apps/web/node_modules` has `react` but not `web/`, and
  `projectFor` in `lib/dts.mjs` dies with
  `ENOENT ... apps/web/node_modules/web/package.json`. The root has both
  (react 19.2.8, @types/react and the self-link), so it is the root:

  ```bash
  node .ds-sync/resync.mjs --config .design-sync/config.json \
    --node-modules node_modules --out ./ds-bundle \
    --remote .design-sync/.cache/remote-sync.json
  ```

  This cost an entire driver run on 2026-07-29.
- **The bundle's `.d.ts` files come from declarations emitted on the spot.**
  `apps/web` is an app, not a lib: it has no `dist/` with `.d.ts`, and without
  that the converter synthesizes `[key: string]: unknown` for the 57
  components, a useless contract for the design agent. Regenerate before any
  build:

  ```bash
  cd apps/web && pnpm exec tsc -p tsconfig.app.json --noEmit false \
    --declaration --emitDeclarationOnly --outDir types --rootDir src \
    --noUnusedLocals false --noUnusedParameters false
  ```

  `findTypesRoot` finds `apps/web/types/` on its own (it is one of the
  candidates), so there is no need to touch `package.json`. The folder is
  generated and is in `.gitignore`. A nice side effect: with real props, 4
  components that used to fall to the floor card now render with synthesized
  defaults.
- **The 37 icons need `dtsPropsFor`.** The extraction heuristic covers
  `export function X(props: P)` but not `export const X: (props: P) => JSX`,
  which is the form in `icons.tsx`; all of them fell into the catch-all. The
  body is identical for the whole set (they share one signature), generated by
  script.
- **Order matters: close the config BEFORE grading**, but only what goes into
  the key. Read from `lib/sync-hashes.mjs` (`configSlicesFor`/`sourceKeyFor`,
  `keyRecipe: 7`), the grade is keyed by: `provider`, `storyImports`,
  `extraEntries`, the bytes of the forks in `.design-sync/overrides/`, the
  component's `overrides.<Name>` **minus** `cardMode`/`primaryStory`, the
  `titleMap` and the bytes of `.design-sync/previews/<Name>.tsx`. Changing
  `provider` or `extraEntries` clears ALL 57 grades (it happened once, on the
  first import, and cost a whole re-read).
  **They do NOT clear**: `dtsPropsFor`, `docsDir`/`docsMap`, `cardMode`,
  `primaryStory`, regrouping by category. The old note blamed `docsDir`; it
  was wrong, and its fear discourages fixing a doc for nothing.

## 2026-07-29: Phase 7a re-sync

`apps/web/package.json` left `0.0.0` (the same commit dropped `keycloak-js`).
`renderHashes` and `sourceKeys` did **not** move: nothing re-rendered
differently.

Three things were fixed along the way:

1. **`docs/Input.md` was lying.** The prose said "the component renders neither
   label nor error message; that belongs to the form that contains it". It
   became false with Phase 7a. Rewritten, and with the reason for `useId()` (it

   not to assemble the label by hand.
2. **`previews/Input.tsx` did not exercise the new API**, hence the stalled
   `renderHashes`. It gained the `ComRotulo` export, ported from
   `LoginPage`/`SetPasswordPage` (label + hint + error with `.invalid` border).

3. **`ToastProvider` had an empty contract** (`[key: string]: unknown`) since
   the first import; the extraction does not catch props declared as an inline
   type literal (`({ children }: { children: ReactNode })`), the same class of
   failure as the 37 icons. Solved with `dtsPropsFor.ToastProvider`.
   `useToast` **is** in the bundle (the synth entry does `export *` of the

## Previews: what I learned while authoring

- **No invented values.** The previews come from
  `apps/web/src/components/*.test.tsx` (factories `makeAction`, `makeEvent`)
  and from real usage in `src/routes/`. The `rm -rf /tmp/build` command in
  ApprovalCard, for example, is the test's.
- **Use real agent keys** (`dev-backend`, `qa`, `anamnese`…, see
  `src/lib/agents.ts`). `ApprovalCard` does `AGENTS[action.actor.id]`: a model
  id (`llama3.1:8b`, which is what the test uses) does not resolve, and the card
  loses name and icon.
- **`AGENTS` and `AGENT_LIST` are NOT exported in the bundle.** Importing from
  `'web'` breaks. Previews that need `AgentDef` repeat the real values inline.
- **Relative time requires an offset from `Date.now()`.**
  `formatRelativeTime` compares with the present, so a fixed date makes the
  text drift ("há 8 h" → "há 30 d") and that clears the grade on every future
  sync. It affects `ActivityFeed`, `EventItem`, `NotificationBell` and
  `CredentialStep`.
- **Four components hide what matters behind internal state.**
  `NotificationBell` (panel), `ModelPicker` (dropdown with the whole catalog),
  `CredentialStep` (`error` and `registering` only exist with the form open) and
  `PrGateTimeline` (the `coverageMatrix` only appears when expanding the
  opinion). Without opening, the main prop produces no visible output and the
  cells end up almost identical. The previews click the trigger in a
  `useEffect`: synchronous, deterministic, with no dependence on animation.
- **`ActivityFeed` hides machine noise**: a preview with `agent.response`
  or `tool.result` renders only "Nenhuma atividade por aqui ainda".
- **`ToastProvider` needs a huge `durationMs`**: the default of 5000 removes the
  toast on its own and the capture becomes a lottery.
- **A `fixed` overlay requires `cardMode: single`** (`Modal`, `ToastProvider`,
  `ModelPicker`); a wide component requires `column` (`Table`, `Tabs`,
  `ProjectCard`). The validate says exactly which, with `[GRID_OVERFLOW]`.

## Risks of a re-sync

What can break when someone runs `/design-sync` again:

0. **The driver does NOT detect a component code change in this shape; you
   do.** In the `package` shape, `sourceKeyFor` only receives `srcSha` when the
   shape is `storybook` (see the `...(shape === 'storybook' ? …)` line in
   `package-build.mjs`). Consequence: a component whose `.tsx` changed is
   reported as `unchanged`, with the old grade carried forward, and nothing asks
   for a recapture. On 2026-07-29 that is exactly what happened with `Input`;
   its `renderHashes` did not even move, because the old preview did not
   exercise the new props. **Before trusting the verdict, do the diff by hand**
   against the last sync's commit:

   ```bash
   git diff --stat <ultimo-sync>..HEAD -- apps/web/src/components
   ```

   And do not pipe that diff through `| tail -N`: with 20+ files `--stat` cuts
   the FIRST lines, which is precisely where `components/` shows up in
   alphabetical order. That is how `Input` almost slipped by.
1. **Forgetting to re-emit `apps/web/types/`.** The folder is gitignored, so on
   a new machine it does not exist, and without it the 57 `.d.ts` files go back
   to `[key: string]: unknown` silently. The build does not fail; it just
   delivers an empty contract. Run the `tsc` above BEFORE the build, always.
2. **`typescript` in `.ds-sync/node_modules` is also not versioned.** Without
   it the `[DTS_PARSE]` check is reported as "skipped" instead of failing, and
   7.x (what `npm i typescript` installs) will not do.
3. **A new component in `apps/web/src/components/` enters with no doc and no
   preview**: it falls into the `general` group (not `Icones`/`Primitivas`/
   `Dominio`) and renders the floor card. The way out is to add
   `.design-sync/docs/<Name>.md` with `category:` and
   `.design-sync/previews/<Name>.tsx`.
4. **A new icon needs three things**: an entry in `dtsPropsFor` (the body is the
   same as the other 37), a preview and a doc. The two scripts that generated
   this in bulk are described here but were not versioned; regenerating is
   trivial from the template of any existing icon.
5. **Changing the palette in `design/tokens.css` invalidates the previews**
   that depend on contrast (all of them). Run the validate and look at the
   contact sheets.
6. **If someone swaps `formatRelativeTime`** for an absolute date, the previews
   that use an offset from `Date.now()` start showing the same date always;
   correct, but the grades clear once.

## Known render warns

Both verified and legitimate; a warn outside this list is news:

- `[TOKENS_MISSING] --item-color, --agent-color, --status-color,
  --urgency-color, --decided-color`: all five are set at runtime by
  `style={{ ['--agent-color']: … }}` in `AgentCard`, `ApprovalCard`,
  `ProjectCard` and the like. They do not exist in any stylesheet, on purpose.
- `[FONT_REMOTE] Archivo, Space Grotesk, IBM Plex Mono`: served by CDN, not
  bundled. Accepted consequence: a preview without network falls back to the
  fallback font.

## 2026-08-04: re-sync after Phases 9-12

**The build broke because of a FONT, and the cause is product.** Commit
`2404d0eb` (ADR 0036) switched the three families from CDN to self-hosted, with
`@font-face` using `url('/fonts/…')` inside `apps/web/src/index.css`. That path
is absolute: it only exists when the app serves `public/`, and esbuild does not
resolve it: 8 errors, the whole build on the floor. There is no config knob for
this, and `lib/bundle.mjs` is a contract (it is not forked).

Solution, in two parts:

1. **The `@font-face` rules moved out to `apps/web/src/fonts.css`**, imported by
   `main.tsx` alongside `index.css`. The app receives exactly the same rules;
   `index.css` (tokens + reset + the five `@keyframes` that 6 components use) is
   importable by esbuild again. **This is a product change**: small and with no
   effect in the browser, but a change. The test
   `apps/web/test/fontes.test.ts` was repointed to the new file and gained an
   assertion that `main.tsx` imports the sheet (without it, splitting the files
   would reintroduce ADR 0036 through another door).
2. **`.design-sync/fonts.css` stopped using the remote Google Fonts `@import`**,
   which had become a lie with ADR 0036, and now declares the SAME rules
   pointing to the `.woff2` files on disk. esbuild inlines them as a data URI,
   so the bundle comes out self-contained. When adding a weight/subset to the
   app, replicate it here: there are two files on purpose (the app needs the
   served url, the bundle needs the disk url) and nothing ties them together
   automatically.

**Risk #0 was confirmed.** The driver reported `changed: 0` with 38 component
files changed since the last sync. Only the `added` partition (9) came out
right. `ProjectCard` was `bad`: `agents` became `rosterGroups` (grouping by
area, ADR 0038) and the old preview passed the old prop: `Cannot read
properties of undefined (reading 'length')`. Preview ported, plus a new export
(`SemOrcamento`) to exercise `noBudget`/`onDefineBudget`, which was the same
trap as `Input` in July: without exercising the new prop, `renderHashes` does
not move and the change stays invisible.

**New components (9).** `Alert`, `Skeleton`, `ProjectCardSkeleton`,
`Textarea` and the icons `AlertCircleIcon`/`EyeIcon`/`EyeOffIcon`/`LogoMark`
got a doc + preview and graduated `good`. The four icons came from the
`CheckIcon` template (same signature), and all four entered `dtsPropsFor`; the
extraction still does not catch `export const X = (props: P) =>`.

**`ModelCatalogSection` stays on the floor card, on purpose.** It fetches data
(`useQuery`/`useMutation`) and would need a `QueryClientProvider` above it.
Putting that in `cfg.provider` would wrap all 57 components and **clear every
grade**: too expensive for one component. It is in
`overrides.ModelCatalogSection.skip` and the reason is written in its doc, so
whoever opens the card does not think it is a defect.

### conventions.md validation (2026-08-04)

Run against the new build: **no name stopped verifying**; every `var(--*)` token
cited exists in the bundle's sheets, and the absence claims (`Tooltip`,
`Popover`, `DatePicker`, "there is no layout/grid/stack") remain true.
`DatePicker` shows up in the automatic sweep as suspect because it is cited
precisely as something that does NOT exist; it is not drift.

**What stayed incomplete, and is a proposal, not a fix:** the header does not
mention the four new primitives: `Alert`, `Skeleton`, `ProjectCardSkeleton` and
`Textarea`. The design agent will not use them without knowing they exist. The
file is human-authored and was not rewritten; the suggestion is one line in
"The primitives" for each, and a mention of the `Skeleton`/`ProjectCardSkeleton`
pair in the loading-states section.

**`overrides.<Name>.skip` is a LIST of exports, not a boolean.** I put
`skip: true` for `ModelCatalogSection` and the build died at
`emit.mjs:368 — boolean true is not iterable` (`new Set(skip ?? [])`). And it
was unnecessary: a component without `.design-sync/previews/<Name>.tsx` already
falls to the floor card by construction. `skip` is for silencing ONE story of a
preview that exists.
